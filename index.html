Agent architecture

Give AI agents responsibilities, not just tasks.

A task ends when it is done. A responsibility holds: the agent watches over something for days rather than for one prompt, notices when it changes and keeps track of what it has found. People stay accountable for what happens next.

Observe deterministically. Judge probabilistically. Remember persistently.

01 · Tasks

Tasks end. Responsibilities don’t.

Most agents are given tasks: a request comes in, work happens, an answer goes out, and the agent forgets. That is the right shape for “fix this bug” or “summarize this thread”. It is the wrong shape for “make sure nothing gets stuck”, which is never finished and never fits in a single run.

A task

Starts
When someone asks.
Ends
When the answer is delivered.
Looks at
Whatever is in the prompt.
Remembers
Nothing, unless told again.
Example
“List the work that is overdue.”

A responsibility

Starts
When it is approved.
Ends
Only when it is withdrawn.
Looks at
The same signals, on every run.
Remembers
Every case it opened, and why.
Example
“Make sure overdue work doesn’t go unnoticed.”

02 · Examples

Five things that should never be forgotten.

None of these is ever done for good, and each is easy to drop when everyone is busy. That is what makes them responsibilities rather than tasks. The examples are illustrative, not a list of current features.

  1. Don’t leave customers waiting.

    A customer reported a problem. The team is working on it, but nobody has given the customer an update in days.

    Responsibility Make sure customers waiting for an answer get one.

    How it works
    Signal
    Customer support issues waiting for a response.
    Instructions
    Identify customers who haven’t received an update in several days and explain why follow-up is needed.
    Case
    Customer waiting for an update on a support issue.

  2. Don’t let reviews go unanswered.

    A developer needs a review. The pull request is ready, but nobody responds. Progress comes to a halt.

    Responsibility Make sure work waiting for review doesn’t get stuck.

    How it works
    Signal
    Work items waiting for review.
    Instructions
    Identify reviews that have had no response for several days and explain why they need attention.
    Case
    Work item waiting for a review.

  3. Make sure customer-reported bugs get a decision.

    Several customers report the same bug. The issues are logged, but nobody decides how urgently they need to be fixed.

    Responsibility Make sure customer-reported bugs are assessed and prioritized.

    How it works
    Signal
    Customer-reported bugs that have no priority yet.
    Instructions
    Identify bugs that have waited several days for a priority and explain why a decision is needed.
    Case
    Customer-reported bug waiting for a priority decision.

  4. Don’t lose customer-reported work.

    A support ticket has been handed over to development. The development issue sits in the backlog while the customer is still waiting.

    Responsibility Make sure customer-reported development work doesn’t disappear into the backlog.

    How it works
    Signal
    Development issues marked as customer-reported that are still in the backlog.
    Instructions
    Identify customer-reported issues that have sat in the backlog for several days and explain why they need to be scheduled.
    Case
    Customer-reported issue waiting in the backlog.

  5. Don’t let releases stall.

    A release is waiting for testing. Nobody has taken ownership of the next step, and the planned release date is getting closer.

    Responsibility Make sure releases waiting for validation keep moving.

    How it works
    Signal
    Work planned for the next release that is waiting for testing.
    Instructions
    Identify release work that has waited several days for testing and explain why it needs to move.
    Case
    Release work waiting for testing.

03 · How responsibilities work

A responsibility keeps watching.

Run after run, mostly while nobody is looking, a responsibility takes the same three steps.

  1. Observe

    Signals identify what needs watching, using queries against your team’s data.

    Signals

  2. Judge

    AI evaluates what needs attention, guided by instructions and evidence.

    AI + rules

  3. Remember

    Persistent cases track unresolved situations and their history across runs.

The agent keeps watching. The responsibility keeps track. People stay accountable.

04 · Accountability

Agents are responsible. People are accountable.

People define the responsibility, set the boundaries, and approve what the agent is allowed to do. The agent keeps watch and can carry out permitted actions. People remain accountable for the outcome.

The agent

  • Runs the signals on a schedule and records what they find.
  • Proposes cases, each citing its evidence. Code, not the model, decides which ones open.
  • Carries out only the actions people have permitted, such as creating a page for each new case.
  • Keeps every case, open or resolved, with the history that led to it.

People

  • Define the signals, the instructions and any actions the agent may take. An agent can draft a responsibility, but it takes effect only once a person approves it.
  • Decide what to do about each case beyond the permitted actions. Reassigning work, escalating a blocker or fixing a defect is their call, not the agent’s.
  • Can check any case: re-run the signal queries behind it, compare the judgment with its evidence and follow its history.
